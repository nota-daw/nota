# Command Palette — требования

Цель: одна точка входа ко всему в Nota, как Command Palette в VS Code. По **⌘⇧P** (macOS) /
**Ctrl+Shift+P** (Windows, Linux) из любого места программы открывается строка поиска, в которой
доступны любое действие, трек, встроенное устройство, плагин и пресет. Выбранный элемент
применяется **к тому месту, откуда палитру вызвали**: в панели устройств устройство встаёт в эту
цепочку, в Modular — на трек, открытый в Modular. Поиск понимает и имена, и смысл
(«тёплый пэд», «reverb for vocals», «компрессор на барабаны»).

Документ построен так: что есть сейчас, требования по приоритетам (P0 → P2) с критериями
приёмки, порядок работ, открытые вопросы.

---

## 1. Что есть сейчас

- **Реестра команд нет.** Меню описано в `MainWindow.axaml` (57 `NativeMenuItem` с жестами).
  Хоткеи разбросаны по `MainWindow.Input.cs` (`OnGlobalTransportKey` в фазе tunnel и
  `HandleKeyDown` в фазе bubble) и по самим вью: Session, Arrangement, Piano roll.
  Список в Preferences → Shortcuts ведётся вручную.
- **⌘⇧P / Ctrl+Shift+P свободен**, конфликтов в коде нет.
- **Поиск в браузере** (`BrowserView.cs`) — это подстрока без учёта регистра по `Name` и `Sub`,
  плюс имена папок пресетов и фильтр по тегам. Нечёткого поиска, синонимов, ранжирования
  и семантики нет.
- **Метаданные, на которые можно опереться**: категории встроенных устройств (Instruments /
  Audio Effects / MIDI Effects), папки заводских пресетов (Pads / Bass / Leads …, Vocals /
  Drums / Mastering …), тип и вендор плагина, пользовательские теги и избранное,
  отпечаток тембра у сэмплов (Smart samples), офлайн-рендер превью пресетов (`PreviewPlayer`).
- **Добавление устройства на трек** уже сведено к `DropBrowserItem(item, trackId)`
  (`MainWindow.Dnd.cs`). Через него работают и панель Devices, и Modular
  (`OnModularDrop` → `_modular.TrackId`). Там же учтены особые случаи: Instrument Rack
  получает новую цепочку, Drum Rack — следующий свободный пэд. Есть и вставка между карточками
  с замещением карточки под курсором (`DeviceChainView.Drop.cs`).
- **Вью**: `MainView { Arrangement, Session, Modular }`, плюс Browser, панель Devices/Clip
  (может открываться отдельным окном), Mixer (отдельное окно), Device window, Piano roll.
- **Modular** пока в фазе 1: это линейная цепочка трека в виде графа, CV-модуляция и
  глобальный вид ещё не работают. Каталога «устройств только для Modular» пока нет.

---

## 2. Требования

Обозначения: **[U]** UI, **[A]** прикладной слой (реестр, индекс, поиск), **[E]** движок,
**[M]** MCP, **[D]** документация (FEATURES, CHANGELOG, nota-docs, Shortcuts).
Каждое применение элемента из палитры — **один шаг undo**.

### 2.1 Вызов и контекст — P0

**CP-1. Глобальный хоткей.** ⌘⇧P / Ctrl+Shift+P открывает палитру из любого окна и фокуса:
главное окно (Arrangement, Session, Modular, Browser, Devices, Piano roll), открепленная панель
Devices/Clip, Mixer window, Device window. Хоткей перехватывается в фазе tunnel, так же как
транспорт, поэтому сфокусированный контрол его не съест. Он срабатывает даже при фокусе в
TextBox, потому что текст такая комбинация не вводит.
Повторное нажатие при открытой палитре её закрывает.
*Приёмка*: хоткей работает из каждого перечисленного места, включая фокус на ручке, слайдере,
поле ввода и ComboBox.

**CP-2. Снимок контекста.** В момент вызова фиксируется `PaletteContext`, и после этого он не
меняется, пока палитра открыта:
- `Origin` — откуда вызвали: Arrangement / Session / Modular / Devices / Browser / Mixer /
  PianoRoll / DeviceWindow;
- `TrackId` — целевой трек (правила ниже);
- `InsertPoint` — для Devices и Modular: после какого устройства вставлять, в какую секцию
  (MIDI FX / instrument / audio FX), внутрь какой цепочки рэка;
- выделение: клипы, слот или сцена, временной диапазон, выбранное устройство, ноты;
- окно, из которого вызвали: туда вернётся фокус после закрытия.

**CP-3. Целевой трек и место вставки.**

| Откуда вызвали | Куда идёт устройство или пресет | Примечание |
|---|---|---|
| Devices (панель или открепленное окно) | цепочка показанного трека, **сразу после выбранной карточки**; если ничего не выбрано — в конец своей секции | если выбрана карточка внутри рэка — в цепочку этого рэка |
| Modular | трек `ModularView.TrackId`. **Устройство Modular** (модулятор, CV-утилита…) появляется **без связей** в центре видимой области (или под курсором, если он над канвасом), соединяет его пользователь. **Обычный эффект / MIDI-эффект / инструмент** встаёт в **конец цепочки** трека (инструмент — по правилам замены ниже) | в списке видны **устройства Modular** (CP-6a.5) |
| Arrangement | выбранный трек; если выбрано несколько треков — первый | если трека нет — см. CP-4 |
| Session | трек выбранного слота или колонки | |
| Mixer | трек выбранного канала | эффекты можно класть и на return, и на master |
| Piano roll | трек редактируемого клипа | |
| Device window | цепочка, в которой стоит устройство, после него | |
| Browser | выбранный трек в Arrangement/Session | Enter работает как двойной клик по элементу в браузере |

Типы устройств ведут себя так же, как при drag & drop. MIDI-эффект идёт в секцию MIDI FX.
Инструмент на треке с инструментом **заменяет** его; клипы, остальные устройства и громкость
сохраняются. На Instrument Rack или Drum Rack инструмент добавляет цепочку или пэд. Аудиоэффект
на MIDI-треке без инструмента не ставится, в строке результата объясняется почему.
*Приёмка*: для каждой строки таблицы результат совпадает с тем, что дал бы drag & drop того же
элемента в ту же точку. Реализация идёт через тот же код (`DropBrowserItem` и вставка по
индексу из `DeviceChainView.Drop`), без копии логики.

**CP-4. Нет целевого трека.** Инструмент или пресет инструмента создают новый трек. Эффект или
MIDI-эффект без трека показываются, но неактивны, с пояснением «Select a track first».
Палитра при этом не закрывается.

**CP-5. Модификаторы применения.**
- **Enter** — действие по умолчанию для контекста (CP-3).
- **⌘Enter / Ctrl+Enter** — на **новый трек** (для инструментов и пресетов инструментов);
  для трека — открыть его в Devices.
- **⌥Enter / Alt+Enter** — **заменить** выбранное устройство вместо вставки после него.
- **⇧Enter** — применить и **оставить палитру открытой**, чтобы добавить подряд несколько
  устройств. Точка вставки сдвигается за только что добавленным устройством.
Подсказка по модификаторам видна в футере палитры.

**CP-6. Цель видна.** В шапке палитры показано, куда пойдёт выбранный элемент, например
`→ Bass · after Nota Vintage` или `→ new track`. Строка меняется вместе с выделенной позицией
и модификаторами. Пользователь не должен гадать, куда добавится устройство.

### 2.2 Что ищется — P0

**CP-6a. Типы элементов** (каждый со своей иконкой и тегом справа):

1. **Actions** — все пункты меню, команды вью (Session: launch scene, stop all, + scene;
   Arrangement: duplicate, split, consolidate, freeze; Piano roll: quantize, legato…),
   переключение вью и панелей, транспорт (play, record, loop, metronome, tap tempo),
   Preferences и их страницы, Export, Undo History. У каждого действия видна клавиша
   (keycap), если она есть.
2. **Tracks** — все треки, включая group, return и master. Enter выделяет трек и показывает
   его в текущей вью (скролл к нему). Подменю треков (CP-11) — P1.
3. **Devices** — встроенные инструменты, аудио- и MIDI-эффекты, рэки, плагины VST3/AU
   (у плагина виден формат и вендор).
4. **Presets** — заводские, пользовательские, наборы Drum Rack / Rhythm, пресеты плагинов
   (сохранённые в Nota **и найденные на диске**, CP-13a). Видно устройство и папку:
   `Warm Strings · Nota Volt · Pads`.
5. **Modular devices** — узлы, которые есть только в Modular: модуляторы, CV-утилиты,
   сплиттеры, миксеры. Они видны **только при Origin = Modular** (в остальных местах их нельзя
   поставить) отдельной секцией сверху. Пока каталога нет (фаза 1), секция пустая. Провайдер
   нужно заложить сейчас, чтобы новые модули Modular появлялись в палитре без её доработки.

**CP-7. Фильтр по типу.** Как в VS Code, работают префиксы:
`>` — действия, `@` — треки, `+` — устройства и плагины, `#` — пресеты, `~` — устройства
Modular. Без префикса ищется всё сразу. Над списком есть чипы All / Actions / Tracks / Devices /
Presets (/ Modular); **Tab / ⇧Tab** переключают их, чип и префикс синхронизированы.
*Приёмка*: `>quant` находит только действия, а `#warm` только пресеты.

**CP-8. Контекстная релевантность.** Действия, которые в текущем контексте неприменимы
(например, «Quantize» без выделенных нот), по умолчанию скрыты. Если запрос точно совпадает с
именем такого действия, оно показывается неактивным с причиной. Действия текущей вью получают
буст в ранжировании.

### 2.3 Лексический поиск — P0

**CP-9. Нечёткое совпадение** в духе VS Code:
- подпоследовательность с бонусами за начало слова, camelCase и смежность символов
  (`afl` → **A**uto **F**i**l**ter, `nv` → **N**ota **V**intage);
- префикс «Nota» игнорируется при скоринге, как в браузере: имя ищется по отличительному слову;
- совпавшие символы подсвечиваются акцентом;
- по каждому полю: имя > алиасы > устройство/вендор > папка/категория > теги.

**CP-10. Опечатки и раскладка.**
- допускается одна опечатка на слово от 4 символов (Дамерау–Левенштейн ≤ 1);
- запрос, набранный в неправильной раскладке, распознаётся: `кумуки` → `reverb`
  (RU↔EN по физическим клавишам);
- поиск нечувствителен к регистру и диакритике.

### 2.4 Семантический поиск — P0 (словарь) / P2 (эмбеддинги)

Принцип: у **каждого** устройства, плагина и пресета есть **семантический дескриптор**, и
запрос сопоставляется с ним, а не только с именем.

**CP-12. Схема дескриптора** (`SemanticDescriptor`, хранится рядом с метаданными устройства
и пресета):

| Поле | Пример | Для чего |
|---|---|---|
| `role` | `reverb`, `delay`, `compressor`, `eq`, `saturation`, `synth.subtractive`, `sampler`, `drum` | что это за устройство |
| `aliases` | `verb`, `comp`, `eq`, `dist`, `ott` | сленг и сокращения |
| `character` | `warm`, `bright`, `dark`, `gritty`, `clean`, `airy`, `punchy`, `wide`, `lo-fi`, `vintage` | характер звука |
| `sound` (пресеты инструментов) | `pad`, `bass`, `lead`, `pluck`, `keys`, `bell`, `arp`, `fx`, `drone` | тип партии |
| `source` (для эффектов) | `vocals`, `drums`, `bass`, `guitar`, `bus`, `master`, `synth` | на чём использовать |
| `task` | `sidechain`, `glue`, `de-ess`, `widen`, `tape stop`, `mastering` | задача |
| `genre` | `techno`, `lo-fi hip-hop`, `ambient`, `trap` | жанр |
| `description` | 1–2 предложения на EN | для эмбеддингов (P2) и тултипа |

Словарь значений `character` / `sound` / `source` / `task` закрытый и версионируется
(`SemanticVocabulary`). У каждого термина есть синонимы на EN и RU: `warm ↔ тёплый, мягкий`,
`pad ↔ пэд, подложка`, `vocals ↔ вокал, голос`. Русский нужен **только для поиска**: в UI
палитры (строки, причины совпадения, тултипы) всё на английском, как в остальном приложении.

**CP-13. Откуда берутся дескрипторы.**
1. **Встроенные устройства** — пишутся вручную и лежат вместе с регистрацией устройства.
   Добавить их — шаг чеклиста `nota-instrument`. Без дескриптора новое устройство не проходит
   тест покрытия (CP-27).
2. **Заводские пресеты** — `sound` и `source` выводятся из папки (Pads → `pad`, Vocals →
   `vocals`, Mastering → `mastering`), `role` наследуется от устройства, `character` и `genre`
   задаются в файле пресета. Пресет без `character` тоже не проходит тест покрытия.
3. **Пользовательские пресеты** — наследуют дескриптор устройства, к нему добавляются токены
   из имени и папки и теги пользователя. При сохранении можно задать характер из того же
   словаря (P1, чипы в диалоге сохранения).
4. **Плагины** — `role` выводится из подкатегорий VST3 (`Fx|Reverb`, `Instrument|Synth`) и
   типа или подтипа AU; к этому добавляется карта известных плагинов по вендору и имени
   (например, `FabFilter Pro-Q` → `eq`) и эвристики по имени (`*verb*`, `*comp*`, `*delay*`).
   Пользователь может поправить дескриптор из контекстного меню (P1).
5. **Анализ звука (P1)** — для пресетов, у которых есть офлайн-превью (тот же рендер, что у
   `PreviewPlayer`), вычисляются `bright/dark` (спектральный центроид), `pluck/pad`
   (атака и затухание), `wide` (корреляция L/R), `distorted` (доля гармоник). Делается это в
   фоне один раз, результат кешируется так же, как Smart samples. Ручная разметка всегда
   важнее анализа.

**CP-13a. Пресеты плагинов с диска (P1).** Индексируются файлы пресетов из стандартных папок
ОС для каждого просканированного плагина:
- VST3 `.vstpreset` — `~/Library/Audio/Presets/<Vendor>/<Plugin>/` (macOS),
  `%USERPROFILE%\Documents\VST3 Presets\<Vendor>\<Plugin>\` (Windows),
  `~/.vst3/presets/<Vendor>/<Plugin>/` (Linux), плюс заводские папки рядом с плагином;
- AU `.aupreset` — `~/Library/Audio/Presets/<Manufacturer>/<Plugin>/` и `/Library/Audio/Presets/`.

Пресет привязывается к плагину по class ID из файла (VST3) или по manufacturer/subtype (AU);
пресеты не установленных плагинов не показываются. Дескриптор: `role` и `sound`/`source` — от
плагина и подпапок (`Bass/`, `Pads/`, `Vocals/`), `character` — из токенов имени. Применение
загружает плагин (если его нет на целевой позиции) и state из файла, одним шагом undo.
Индекс обновляется после rescan плагинов и по изменению файлов в этих папках
(watcher, без полного пересканирования). Эти же пресеты видны во вкладке Presets браузера.

**CP-14. Разбор запроса (P0, без ML).** Запрос токенизируется, каждый токен ищется в словаре
синонимов, получаются фасеты.
`warm pad` → `{sound: pad, character: warm}`, тип = пресет инструмента.
`reverb for vocals` → `{role: reverb, source: vocals}`.
`компрессор на барабаны` → `{role: compressor, source: drums}`.
Служебные слова (`for`, `on`, `на`, `для`) отбрасываются. Токены, которые не нашлись в
словаре, идут в лексический поиск (CP-9).

**CP-15. Ранжирование.** Итоговый скор складывается из:
`lexical × 1.0 + facets × 0.8 + context × 0.3 + frecency × 0.3 + favorite × 0.2`.
Веса настраиваются и проверяются тестами.
- Точное совпадение имени всегда выше чисто семантического.
- Семантические попадания выделены: под строкой показано, почему элемент нашёлся, например
  `warm · pad`. Пользователь должен понимать, почему ему показали `Velvet Choir` на запрос
  «тёплый пэд».
- frecency — частота и давность использования из палитры и браузера; хранится в Settings.

**CP-16. Эмбеддинги (P2).** Локальная мультиязычная sentence-embedding модель (ONNX, ≤ 100 MB)
загружается через существующую инфраструктуру AI Models (Preferences → Downloads).
Индексируется `description` + фасеты, поиск идёт по косинусной близости и добавляется в
скор (CP-15) как ещё одно слагаемое. Без модели палитра полностью работает на словаре
(CP-14). Сеть не нужна никогда.

### 2.5 UI — P0

**CP-17. Вид.** Оверлей по центру сверху (около 20 % высоты окна от верха), ширина 640 px,
до 12 видимых строк. Стиль Ember (`nota-design`): поверхность `SurfaceCard`, бордер, тень,
акцентная рамка поля. Окно под палитрой не затемняется, чтобы было видно цель. Палитра
открывается в том окне, из которого её вызвали (главное, открепленные Devices, Mixer).

**CP-18. Строка результата**: иконка типа → имя с подсветкой → вторичный текст
(устройство · папка, или вендор · формат, или тип трека) → справа keycap действия или тег
типа. Секции (Recent, Actions, Tracks, Devices, Presets, Modular) показываются, только когда
запрос пустой или это режим All.

**CP-19. Пустой запрос** показывает Recent (последние 5 элементов, применённых из палитры) и
Suggested для контекста: в Devices — часто используемые эффекты, в Modular — модули, в
Session — Launch Scene / Stop All, и так далее.

**CP-20. Клавиатура**: ↑ ↓, PgUp / PgDn, Home / End, Enter и модификаторы (CP-5), Tab (CP-7),
Esc закрывает и возвращает фокус туда, откуда палитру вызвали. Space внутри палитры вводит
пробел; транспорт в этот момент не срабатывает. Мышь: наведение выделяет, клик применяет.
Клик вне палитры её закрывает.

**CP-21. Прослушивание (P1).** **→** (стрелка вправо) или **⌘P** на пресете или устройстве
проигрывает превью через `PreviewPlayer`: тот же звук, что в браузере, и тот же кэш.
**↑ ↓** при включённом Auto играют следующее. Рядом со строкой видна мини-волна.

### 2.6 Производительность — P0

**CP-22.** От нажатия хоткея до готовой к вводу палитры проходит **≤ 50 ms**. Пересчёт
результатов на одно нажатие клавиши — **≤ 8 ms** на индексе в 20 000 элементов
(1 000 плагинов, 15 000 пресетов, 300 действий, 200 треков). Поиск идёт синхронно в UI-потоке
по готовому индексу, без аллокаций в горячем пути.

**CP-23. Индекс** строится в фоне при старте и обновляется инкрементально: после rescan
плагинов, сохранения или удаления пресета, добавления или переименования трека, смены
библиотечных папок. Если палитру открыли раньше, чем индекс готов, она уже работает по готовой
части, а в футере видно `indexing presets… 62 %`.

### 2.7 Архитектура — P0

**CP-24. Реестр команд** `ICommandRegistry` в `Nota.Application` (без зависимости от Avalonia):
```
PaletteCommand { Id, Title, Category, Aliases[], Gesture?, Descriptor?,
                 Func<PaletteContext, Availability> CanExecute,
                 Action<PaletteContext, ApplyMode> Execute }
```
- Пункты меню из `MainWindow.axaml` и команды вью **регистрируются в реестре**. Меню и хоткеи
  вызывают команды по `Id`, логика больше не дублируется.
- Список в Preferences → Shortcuts и страница shortcuts в nota-docs генерируются из реестра,
  что заодно закрывает дрейф, с которым сейчас борется `nota-shortcuts`.
- Провайдеры элементов: `ActionProvider`, `TrackProvider`, `DeviceProvider` (встроенные и
  плагины), `PresetProvider`, `ModularProvider`. Новый тип элемента — это новый провайдер.

**CP-25. Применение** устройств и пресетов идёт через один сервис вставки, который
используют и drag & drop, и палитра: `InsertDevice(item, target, mode)`. Он вынесен из
`DropBrowserItem` и `DeviceChainView.Drop` (CP-3). Один вызов — одна undo-группа
(`BeginUndoGroup` / `EndUndoGroup`).

### 2.8 Треки — P1

**CP-11. Действия над треком.** В результате-треке **→** открывает подменю: Select, Show in
Devices, Open in Modular, Rename, Color, Mute, Solo, Arm, Freeze, Duplicate, Delete. Запросы
вида `@bass mute` или `mute bass` сразу дают действие над треком.

### 2.9 Прочее — P1 / P2

- **CP-32 (P1). Поиск браузера на том же индексе.** Поле поиска в браузере использует тот
  же индекс и ранжирование (CP-9…CP-16) вместо подстроки по `Name`/`Sub`, в рамках
  активной вкладки и включённых тегов. Сохраняется текущее поведение: раскрытие папок вокруг
  совпадений, поиск по имени папки («Mastering»), счётчик совпадений. Под строкой с
  семантическим совпадением — та же причина (`warm · pad`). Golden-тесты (CP-27) гоняются и
  для браузера.
- **CP-26 (P1). Параметры как цель.** `cutoff` в Devices находит параметры устройств
  выбранного трека; Enter фокусирует ручку, после этого можно вводить значение.
- **CP-28 (P2). Сэмплы и проекты.** Типы `Samples` (с фасетами Smart samples: BPM, key,
  loop/one-shot, тембр) и `Projects`.
- **CP-29 (P2). MCP.** Инструмент `palette_search(query, kinds?)` возвращает элементы со
  скором и фасетами, `palette_apply(id, target)` применяет их. Так ИИ получает тот же
  семантический поиск устройств и пресетов.
- **CP-30 (P2). Remote.** Поиск и добавление пресета с телефона на выбранный трек.

### 2.10 Качество — P0

**CP-27. Тесты.**
- Покрытие: у каждого встроенного устройства есть `role` и `aliases`, у каждого заводского
  пресета есть `sound` или `source` и хотя бы один `character`.
- Golden-набор запросов → ожидаемые элементы в топ-3 (≥ 50 запросов на EN и RU):
  `warm pad`, `тёплый пэд`, `verb`, `кумуки`, `sidechain`, `de-esser`, `bass for techno`,
  `компрессор на барабаны`, `afl`…
- Контекст: для каждой строки таблицы CP-3 результат применения совпадает с результатом
  drag & drop.
- Производительность: бенчмарк на синтетическом индексе из 20 000 элементов (CP-22).
- Undo: применение, затем ⌘Z, возвращает проект в исходное состояние.

**CP-31. Документация.** Записи в FEATURES.md и CHANGELOG, страница в nota-docs (EN + RU),
хоткей в Preferences → Shortcuts (через `nota-shortcuts` или генерацию из реестра).

## 3. Порядок работ

1. **Реестр команд** (CP-24) и перевод меню и хоткеев на него. Без этой основы действия
   в палитре не появятся.
2. **Сервис вставки** (CP-25), вынесенный из drag & drop, с тестами на таблицу CP-3.
3. **Оверлей палитры**: хоткей, снимок контекста, фильтры, клавиатура, строка цели
   (CP-1…CP-8, CP-17…CP-20).
4. **Индекс и лексический поиск** (CP-9, CP-10, CP-22, CP-23).
5. **Словарь и дескрипторы** для встроенных устройств и заводских пресетов, разбор запроса,
   ранжирование, golden-тесты (CP-12…CP-15, CP-27).
6. **Плагины**: дескрипторы из VST3/AU и карты вендоров (CP-13.4).
7. **P1**: перевод поиска браузера на общий индекс (CP-32), пресеты плагинов с диска
   (CP-13a), подменю треков, прослушивание, анализ звука, параметры, ручная правка
   дескрипторов.
8. **Modular-провайдер** подключается вместе с каталогом модулей Modular (фаза 2 Modular).
9. **P2**: эмбеддинги, сэмплы и проекты, MCP, Remote.

---

## 4. Принятые решения

1. **Modular**: устройство Modular появляется без связей; обычный эффект встаёт в конец
   цепочки (CP-3).
2. **Пресеты плагинов** индексируются и с диска — `.vstpreset`, `.aupreset` (CP-13a).
3. **Браузер** переходит на тот же индекс и поиск (CP-32).
4. **Язык UI** — только EN; русский используется только для сопоставления запросов (CP-12).
