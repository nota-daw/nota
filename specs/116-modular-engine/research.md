# Research Notes: Modular Native Engine Architecture (`specs/116-modular-engine`)

## 1. Multi-DLL Performance & Real-Time State Ownership
- **Finding**: Putting `Simd.h`, `BufferOps`, `StereoOps`, `ComplexOps`, or `FastMath` functions out-of-line behind a DLL boundary introduces indirect PLT/IAT calls per block/sample and blocks vector auto-inlining. Meanwhile, header-defined globals (`SilenceGate.h:24-25`, `Device.h:44-59`, `RackCore.h:151-154`, `EditorKeys.h:34-37`) would duplicate state across every `.dll`/`.dylib`/`.so` importing those headers.
- **Decision**: Keep vector/math kernels header-inline in `nota_math`, `nota_dsp` lightweight helpers header-inline, and move ALL mutable/singleton/atomic state + `RealFft` Pimpl + `DeviceRegistry` + `AudioCodecRegistry` + `AudioDriverRegistry` into `.cpp` files exported with `NOTA_*_API` from their single owning DLL.

## 2. Separating `pluginscanner` from `pluginhost` (Option A)
- **Finding**: `src/native/nota.engine/CMakeLists.txt:419-434` previously merged `OutOfProcessScanner`, `PluginCatalog`, and `abi_pluginscanner` into `nota_pluginhost` via an `INTERFACE` target solely because `STATIC` JUCE linking caused ~11k duplicate symbols. Meanwhile `OutOfProcessScanner.h` and `PluginCatalog.h` leaked `juce::PluginDescription` and `sharedFormatManager()` into hosting code, and hardcoded VST3/AU paths (`kFormatsWithDefaults`, `removeMissingVst3OnDisk`).
- **Decision**: Move pure JUCE-free contracts (`PluginFormatKind`, `PluginFormatDescriptor`, `PluginDescriptor`, `IPluginCatalog`, `IPluginScanner`, `IPluginHost`) into `nota_dsp`. Build `nota_pluginscanner` (`SHARED` + `nota-scanworker` + `nota-scanner-selftest`) and `nota_pluginhost` (`SHARED` + `nota-render-probe`) independently—both applying hidden default visibility + `-exported_symbols_list` (macOS) / `--version-script` (Linux) so zero `juce::*` symbols export dynamically. Encapsulate JUCE VST3/AU discovery/probing inside `pluginscanner/src/backends/juce/` via `IPluginFormatBackend` & `PluginFormatRegistry`, and `OutOfProcessScanner`/`nota-scanworker` wire protocol via `ScanWireCodec`, laying clean foundations for CLAP, LV2, and JUCE-independent VST2 later.

## 3. Unifying `io/` (Audio Output/Input + MIDI + Gamepad)
- **Finding**: Legacy `src/audio_io/` mixed `AudioBackend`/`AudioInput` (split interfaces taking raw OS `uint32_t`), `AsioSession::sharedAsioSession()` (accessed directly from C ABI `nota_engine_audio.cpp`), `MidiInput`/`MidiOutput`/`MpeInput`, and `GamepadInput` (UI-polled `GameController` note/MIDI-learn device).
- **Decision**: Rename module cleanly to `modules/io/` (`nota::io` alias, `libnota_io.*` output name to prevent system `libio.*` clashes), organized internally into strictly independent `audio/`, `midi/`, and `gamepad/` subdirectories/namespaces. Introduce `IAudioDriver`, `IAudioOutputStream`, `IAudioInputStream`, `AudioDriverRegistry`, and coupled duplex stream factories to remove all OS `#ifdef`s and global ASIO singletons from `Engine` and `c_abi`. Move `FakeAsioDriver` self-test (`nota_engine_audio.cpp:300-632`) to native `test_io`.

## 4. Object-Oriented C++20 `Engine::*` Handle Model
- **Finding**: `Engine.h` (3,235 lines) exposes flat C-style integer ID methods (`setTrackVolume(id, ...)`, 16 duplicate `add<Synth>Track()` methods, etc.), tightly coupled to 13 monolithic `Engine_*.cpp` files (`Engine_Tracks.cpp` 4,792 lines, `Engine_Render.cpp` 4,019 lines).
- **Decision**: Design `nota::Engine` around lightweight reference handles (`Engine::Track`, `Engine::Clip`, `Engine::Device`, `Engine::Parameter`, `Engine::Rack`, `Engine::RackChain`, `Engine::Session`, `Engine::Scene`, `Engine::Slot`, `Engine::AutomationLane`, `Engine::Modulator`, plus domain facades `Engine::Transport`, `Engine::Mixer`, `Engine::AudioIo`, `Engine::MidiIo`, `Engine::GamepadIo`, `Engine::History`, `Engine::Diagnostics`) holding safe weak ownership (`std::weak_ptr<Engine::Impl>`) + stable IDs, declared inside `Engine.h` and defined in separate <180-line self-contained headers. The optional C ABI layer (`modules/c_abi/` -> target & binary `nota_engine`) delegates cleanly to OOP `Engine::*`, `AudioCodecRegistry`, and `IPluginScanner`.

## 5. `clangd` and `compile_commands.json` Tooling
- **Finding**: Inspected `src/native/nota.engine/build/compile_commands.json` and `which clangd` (Apple `clangd` 21.0.0). Current CMake passes both `-arch arm64 -arch x86_64` and `-flto=thin` in every compile entry, breaks header mode consistency via per-file `LANGUAGE OBJCXX` overrides on `.cpp` files in `pluginhost/`, and dumps 16 global `-I` paths across targets without a `.clangd` config.
- **Decision**: Introduce `NOTA_UNIVERSAL_BINARY` (`OFF` in dev presets, `ON` in `release` and `scripts/build*.sh`), provide `src/native/nota.engine/CMakePresets.json` (`dev`, `dev-cpp`, `release`) and root `.clangd` (`CompilationDatabase: src/native/nota.engine/build-dev`, `Remove: [-arch, -flto, -flto=thin]`, `UnusedIncludes: Strict`, `MissingIncludes: Strict`, CPM `_deps/` suppression), convert macOS ObjC++ bridges to `*_mac.mm`, add `.cache/` to `.gitignore`, and validate every public header standalone via `test_headers_compile`.
