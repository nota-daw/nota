# Research: Phase 6 — Streaming Disk Audio Sources & Hybrid Anticipative Buffering (`nota-daw/nota#1050`)

## Decision 1: Non-Breaking `AudioSource` / `StreamingAudioSource` Composition in `SampleBuffer`

- **Decision**: Introduce `AudioSource` (`MemoryAudioSource`, `StreamingAudioSource`) in `src/native/nota.engine/src/media/` and embed `std::shared_ptr<AudioSource> source` on `SampleBuffer`, keeping `SampleBuffer::samples` populated ONLY for in-memory sources while keeping it empty for `StreamingAudioSource`. Delegate `SampleBuffer::readStereo()`, `at()`, `scanSquares()`, `scanRange()`, `Engine::sampleRead()`, and block mixing cleanly when `samples.empty() && source`.
- **Rationale**: Over 30 files hold `std::shared_ptr<SampleBuffer>` (`AudioClip`, `AudioTake`, `SessionSlot`, `Sampler`, `GrainSynth`, `Mosaic`, `RhythmMachine`, `AudioImportJob`, `findSampleById`). Preserving `SampleBuffer` as the shared identity/overview handle while swapping only the backing storage (`MemoryAudioSource` vs `StreamingAudioSource`) keeps 100% compatibility across UI waveforms, warp markers, tempo/key analysis, and project `.als`-like bundling (`nota_sample_read`) without massive churn or virtual call penalties on hot in-memory loops.
- **Alternatives considered**: Replacing `std::shared_ptr<SampleBuffer>` globally with `std::shared_ptr<AudioSource>`. Rejected because it breaks every instrument/rack/import/persistence signature unnecessarily and adds virtual dispatch on small in-memory one-shots (`Sampler`, `Rhythm`, `GrainSynth`).

## Decision 2: Lock-Free Wait-Free Seqlock Page Ring + Sleep-on-Idle `StreamingIoScheduler`

- **Decision**: Implement `StreamingAudioSource` using:
  - Fixed page size `kPageFrames = 8192` frames (~64 KB stereo) and `kRingPages = 32` slots (~2 MB resident window per stream regardless of file length).
  - Pre-decoded immutable head cache (`kHeadPages = 2` = `16,384` frames) populated on open so frame-0 starts and loops from start never stall on cold disk reads.
  - Per-slot `alignas(64)` `PageSlot` with atomic `seq` seqlock (`odd` = writer active, `even` = stable), `pageIdx`, and pre-allocated `std::vector<float> data`. Audio-thread readers perform pure atomic acquire loads (`readStereo`/`at`), retrying the fast lock-free load if a slot's `seq` is mid-update — **zero mutexes, zero allocations, zero syscalls (`AR-6`)**.
  - A shared background `StreamingIoScheduler` worker thread that maintains `[cursorPage - 2, cursorPage + 20]` lookahead while playback rolls, waits on `condvar.wait_for(10ms)` once full during active transport, and parks on indefinite `condvar.wait()` whenever idle/stopped (`0.0%` idle CPU).
  - Dedicated offline synchronous page fault path (`allowSyncFill = true` during `renderOffline()`, `nota_sample_read()`, `TempoDetect`, `SampleAnalysis`, warp builders) using a separate sync decoder handle so offline exports & smoke tests are 100% deterministic (`diff == 0.0`).
- **Rationale**: Using `dr_wav`, `dr_flac`, and `dr_mp3` (already vendored and UTF-8 / Windows `widePath` safe) requires zero third-party dependencies (`Constitution III`) and supports frame-accurate seeking (`drwav_seek_to_pcm_frame`, `drflac_seek_to_pcm_frame`, `drmp3_seek_to_pcm_frame`).
- **Alternatives considered**: OS `mmap` over raw WAV files. Rejected because FLAC and MP3 cannot be directly mapped as decoded f32 PCM, `mmap` page faults can block the real-time audio thread violating `AR-6`, and Windows/compressed formats require decoder state.

## Decision 3: Single-Owner Anticipative Lookahead (`HybridBufferController`) for Deterministic Non-Live Tracks

- **Decision**: Create `HybridBufferController` (`src/native/nota.engine/src/engine/HybridBufferController.h/.cpp`) operating cleanly in real-time callback mode (`deviceBlock_ == true`) when `mode == HybridBufferMode::Auto` and `pool_->workerCount() > 0` (`renderThreads != 0`).
  - **Live-track partition** (always rendered inside driver callback for hardware latency): Group/Return/Master buses, armed tracks, monitored tracks, live/routed MIDI tracks (`midiFromTrackId() >= 0` or held keys), live Session slots, capture/record-tap tracks, sidechain producers/consumers (`keyNeeds != 0` or `trackFeedsRoute` or `trackFeedsMidiKey`), tracks targeted by dynamic cross-track modulators, or tracks with `!canProcessTrackParallel()`.
  - **Anticipative partition** (rendered ahead in `kChunkFrames = 1024` background chunks up to `kLookaheadFrames = 4096` frames into pre-allocated `8192`-frame per-track circular rings): static/arrangement `AudioClips` and `MidiClips` + `Frozen` tracks + their deterministic FX/device chains.
  - **Post-fader live mix preservation**: Track `volume`, `pan`, `mute`, `solo`, `send[0..3]`, `cue`, and metering execute on the audio callback thread in `writeLeafTaps()` / `finalizeMixBlock()`, preserving instant zero-latency fader/mute response!
  - **Single-owner concurrency guarantee**: Atomic per-track `workerInFlight` guard + `epoch_` generation fence guarantees that background workers and the audio thread NEVER execute `Device`/`Instrument` stateful `process()` concurrently for the same track. Any graph edit (`publishRaw`), seek (`seekBeats`), loop/BPM change, arm/monitor toggle, or device parameter edit (`deviceSetParam` / `midiEffectSetParam`) increments `epoch_`, immediately rejecting stale chunks and cleanly handing control back.
- **Rationale**: Trying to share `Engine::rs_` or run `Engine::applyAutomation()` across future and current beats in parallel would create data races. Giving `HybridBufferController` its own isolated pre-allocated chunk workspace (with per-track arrangement MIDI computation + per-track device automation evaluation cleanly separated from live faders) guarantees zero race conditions, zero `AR-6` allocations, and `0.0%` idle CPU when stopped or in offline mode.
- **Alternatives considered**: Running full graph snapshots ahead into a master bounce queue. Rejected because it would freeze live faders/mutes/solos and armed monitoring latency to lookahead size, defeating the purpose of *hybrid* live + anticipative buffering.
