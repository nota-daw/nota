# Nota design language

Nota's style guide, grown from Saine's design system (`../saine/DESIGN.md`) applied to
Nota: a flat, grey shell so the track colours carry the content; depth only inside
device cards; orange in three clearly different strengths; one typeface with fixed-width
digits. The layout and every control stay where they are: the guide sets only how they
are drawn.
Colour is a **theme**: one fixed look, dark or light, that gives every token a value —
Studio Dark (the default), Studio Light, Ember Graphite, Ember Paper. Layout, type, shapes
and where orange goes are the same in every theme. Preferences → Appearance picks a theme
or Follow system (a dark-mode and a light-mode theme); the switch is live. `DESIGN.md` is
Nota's guideline as Nota implements it, plus the accepted departures and what is not built
yet.

If `DESIGN.md` / `DESIGN.html` disagree with the theme files, **the theme files win** and
the docs need fixing (`design-html.py` warns when a hex in `DESIGN.md` no longer matches).
Say so rather than propagating the drift. The app is being redrawn in phases on
`ui/style-guide`: check `DESIGN.md` § Known drift before assuming a part already looks the
new way.

> This skill deliberately does **not** restate token values. An earlier version did, and
> it drifted a whole palette out of date. Read the files.

## Non-negotiables

Many of these are enforced by `DesignTokenCheck`; the smoke test fails when one breaks.

- **Keep every control.** Redrawing never moves, removes or merges a control, label or
  value; a device keeps what it had in 0.56.1, in the same groups. A value is always
  visible next to its control, never only in a tooltip.
- **No literals in views.** XAML: `{DynamicResource Brush.*}` / `{DynamicResource Shadow.*}`
  (a `StaticResource` cannot follow a theme change) and
  `{StaticResource Radius.*|Control.*|Space.*}`. C#: `NotaPalette` (a slot,
  `Wash(slot, alpha)`, `InkOn(fill)`, `Ink("#hex")` for a one-off device hue),
  `NotaRadius`, `NotaSize`, `NotaSpace`, `NotaDepth`, `NotaFonts`, `NotaType`. No hex
  outside `Ink()`, no RGB typed as numbers, no `Colors.X` / `Brushes.X` except
  `Transparent`, no font family names, no `new BoxShadows` in a view.
- **Nothing may snapshot a colour.** `new SolidColorBrush(slot.Color)`, a
  `static readonly Color` or brush built from the palette, or a static array of palette
  colours freezes the view in one theme. Use the slot, `Wash`, `InkOn`, `Derived`, a
  property, or read `.Color` inside `Render`. Track colours:
  `ArrangementView.TrackBrush(index)`.
- **A flat, grey shell.** Toolbar, browser, track headers, mixer and editors are flat:
  panels meet on a 1 px `Seam`, items inside a panel are split by `Rule`. Shell controls
  have **no border**: they sit on the faint `Well`, and an icon button shows it only on
  hover. Nothing in the shell is raised.
- **Depth only in devices.** The device card (and a Modular node) is raised
  (`Shadow.Card`), its sections are pressed in (`DeviceSection`, `Shadow.Section`), its
  controls sit in grooves (`Groove`, `Shadow.Groove`), and the picked option rises out of
  its groove (`Shadow.Lifted`). Depth is slightly different greys, thin lines and 1–2 px
  shadows: no gradients, glow or textures. Only a floating layer drawn in the main window
  (`Shadow.Popover`, `Shadow.Modal`) blurs more than 2 px; menus and popups get a seam
  ring only (Avalonia clips a popup's shadow at its window edge).
- **Orange has three jobs, and only three.** **Live** — solid `Accent` with derived ink:
  playing, recording, the playhead, the loop, a switch that is on inside a device, power,
  the current device tab's underline. **Picked** — the soft tint (`AccentSoft`) with
  orange text or icon (`AccentBright` in dark themes, `AccentPale` in light ones): the
  chosen segment, the current view, a tool that is on, a chip that is on. Never a solid
  fill. **Values in devices** — orange lines on a quiet fill: knob arcs, the 3 px line on
  a value bar, the selected EQ point. Outside devices values stay grey (a flat knob is
  `TextTertiary` at rest; a shell slider is a quiet grey fill with an ink-2 line) and turn
  orange only while being set. A selected clip or Session slot gets a 1 px outline in ink
  1, never orange. The one accepted extra: a hovered menu item keeps its full orange fill.
  A modulation arc keeps its source's colour. There is no second accent.
- **Semantic fills with derived ink.** Mute on = `Mute` (amber), solo on = `Solo` (blue),
  arm / record on = `Record` (red), solid, with `NotaPalette.InkOn(fill)` for the text or
  glyph — never a fixed label colour on a themed fill. Meters run `MeterSafe` to 70 %,
  `MeterHot` to 88 %, `MeterOver` above. Graph chromas (viz ink · teal · rose · blue) live
  only inside graphs, after shade has been tried; devices lose their teal / olive / rose
  identity colours.
- **The corner scale.** `Radius.Docked` 0 (docked panels) · `Card` 9 (device card, view
  group, modal) · `Group` 7 (icon button, chip, segment group, device section, menu,
  Modular node) · `Field` 6 (field, dropdown, clip, pill, graph window) · `Cell` 5
  (segment cell, track button, tooltip, Session slot) · `ValueBar` 4 · `Switch` 3 ·
  `Fine` 2 (switch knob, notes, plot bars, meter channel). Pick the name for what you draw.
- **One typeface: Geist, with tabular figures.** Every word and number, no monospace face.
  `NotaFonts.InstallTabular()` turns on `tnum` app-wide; custom-drawn text is a
  `NotaFormattedText`, never a bare `FormattedText`. Use the scale in `DESIGN.md` § Type
  (readout 16 / 500, device name 12 / 600, track name 12 / 580, body 11, value 10.5, label
  10, device label 9.5, column head 9.5, key letter 9.5 / 650; the user's Text size steps the
  shell's text by −1…+2 pt through `NotaTextSize`, so never read the setting in a view; device
  cards are `NotaTextSize.Fixed` and keep their size); a unit sits beside its value
  in ink 3. Nothing under 7 px.
- **Sentence case, no tracking — every label.** Menu items, command titles, palette
  headings, window titles, tooltips, buttons, tags: "Save as…", "Export audio", "Analog
  poly". Capitals stay only on acronyms and units (`NotaText.Fixed`), "Nota …" product and
  device names, the view names (Arrangement, Session, Modular, Mixer), proper nouns, and a
  page after "Settings: ". Route labels through `NotaText.Label`. Never
  `ToUpperInvariant()` a label, never set `LetterSpacing`. `RunLabels` fails on an all-caps
  or Title Case literal; `LabelAllowList.txt` is for data only.
- **Never see-through, opacity is not a state.** An unavailable option is ink 4
  (`TextDisabled`) with nothing picked; use `Inactive.Set` for a subtree. The see-through
  wells are fills, not a state. The only allowed `Opacity` is a drag ghost.
- **State changes colour only** — never size, border width or position (no 1 px press
  shift). Hover and colour transitions 120 ms ease-out; meters, playhead and spectra are
  never animated.
- **Numbers are set, not printed.** The app installs a display culture (point decimal,
  U+2212 minus — typed literals too, `"−12"`, never `"-12"`). Put a thin space (` ` in
  source) before units, keep precision fixed (dB one decimal, tempo two, percent whole, Hz
  up to 999 then `3.2 k`) — use `NotaNum` helpers. Ranges take an en dash, closed between
  plain numbers (`1–127`), spaced when an endpoint has a space (`20 Hz – 20 kHz`).
- **Every icon is a `Glyph`.** `Controls/Glyph.cs` is the one icon set: drawn on a
  24-unit grid, scaled as a whole (never `Stretch.Uniform`), 16 in a button; stroked parts
  take the shared 1.6-unit pen with round caps and joins, filled parts the ink (transport
  shapes, OS marks, `StarFilled`, carets). Icons are ink 2 at rest, orange on the soft tint
  when on, derived ink on solid orange. A missing icon is a new `GlyphKind` with a one-line
  comment, never a path in a view — `RunIcons` fails on `Geometry.Parse`, `Data="M…"` or a
  path string outside `Glyph.cs`. No unicode symbols (`■ ▶ ● ✓ ★ ▾`…) and no emoji as
  text. `·` separates meta; `→` in prose is fine.
- **Copy:** English. Labels one word where it fits, no vowel-dropped contractions
  (`Feedback`, not `Fdbk`; `Freq`/`Reso`/`Thresh` are allowed). Tooltips short and
  verb-first. Empty states are one line of ink 3, centred.

## Device cards

- **Every device keeps its 0.57 layout and size**: 700 × 260 (`DeviceCardKit.CardH`,
  `IDeviceBody.Width`), the same sections in the same places, its status line inside the
  body. The style guide restyles the elements, never the layout; repacking a card, growing
  its width or its text is a separate decision for Chris (a full redraw was reverted on
  Oct 26 for making the cards cramped and too large). Corner 9, raised.
- **Header 22** (`BuildCardShell` in `DeviceChainView.Shell.cs` — every card uses it,
  racks, the generic instrument card, plug-ins and Sends included; never build a header of
  your own), in fixed slots: **name · preset menu · type tag and accessories · power**.
  Tabs stay in the body. A/B, move and delete go in the right-click menu.
- **Inside:** capped knobs (36, 34 secondary, 44 main, 24 in a table row) with an orange
  arc, value bars for every slider (9 high in a groove, soft fill, 3 px orange line;
  upright faders through `UprightBar`), segment groups in a groove with the picked cell
  tinted, switches 18 × 10, the round pitch and mod wheels, Geist only, device text on the
  `NotaType.Device*` scale (name 12, rows 9, knob text 8, axes 7.5). Graphs go through
  `NotaGraph` (no fills under curves, orange only on the selected node).
- A bypassed card keeps its layout and takes the unavailable look; a selected card has a
  1.5 px orange ring outside its outline.

## Adding a control

Reuse before writing: `Knob` (snaps to 34 / 36 / 44 · 24 inline · 28 flat),
`DeviceCardKit.KnobCell`, `SwitchTrack` / `DeviceCardKit.Switch` (18 × 10),
`DeviceCardKit.Segments`, `SliderTrack` / `DeviceCardKit.SliderRow` (the value bar),
`VFader`, `MiniFader`, `PanBar`, `DragNumber`, `PerformWheel`, `MeterBar` / `StereoMeter` /
`GrMeter`, `ValueEntry` / `ValueText`, `Glyph`, `NaBadge`. Sizes and specs: `DESIGN.md`
§ Buttons, § Knobs, sliders, meters and wheels, § Fields.

A new value control **must** match the interaction contract:

- Vertical drag, up increases, full range over ~140 px; Shift/Ctrl/⌘ for fine steps;
  `ns-resize`; a click never jumps the value (a horizontal bar also follows a drag along
  its own axis)
- Double-click on the control restores the default
- ⌥/Alt-click, or a double-click on the read-out, types a value in place (`ValueEntry`)
- Right-click opens the parameter menu, merged into the CV-modulate / MIDI Learn menu;
  drag with the left button only
- `GestureBegin` / `GestureEnd` bracket `BeginAutomationWrite` / `EndAutomationWrite`
- Register with `MidiLearn.Bind`
- Live-follow refresher that **skips while dragging**
- The value is always visible, in tabular figures so its width does not jump
- Inside a device its value is an orange line; outside, grey at rest and orange only while
  it is being set

## Applying it (Avalonia)

- `NotaTheme.axaml` is merged in `App.axaml`; `NotaThemeService` applies the colour theme
  (resolved from settings by `Nota.Application.Appearance`) to both layers.
  `NotaFonts.InstallTabular()` and `NotaNum.Install()` run before the XAML loads.
- Use the control styles and `TextBlock` role classes in `NotaTheme.axaml` rather than
  styling a control in place; a primary action is set apart by weight (600) and one tone
  step, never by colour.
- Elevation and depth: `BindResource(Border.BoxShadowProperty, "Shadow.Card" |
  "Shadow.Section" | "Shadow.Groove" | "Shadow.Lifted" | "Shadow.Popover" | …)` in a view,
  `NotaDepth.Groove` / `Section` / `Lifted` in a `Render` — never a literal.

## When you change a token

1. Change the value in each theme file in `Theme/Themes/` it should change in (both Studio
   themes at least). A **new** token is a `T(nameof(X))` slot in `NotaPalette`, a value in
   **every** theme file (the smoke test names a file that lacks it), and a `KeyMap` entry
   if XAML uses it.
2. Every theme must still pass the readability bar (`DESIGN.md` § Readability bar).
3. Run `python3 scripts/design-html.py` and update the tables in `DESIGN.md` (the script
   warns about any hex there that no longer matches).
4. Check every theme — in the app and in `DESIGN.html` (`?variant=light`,
   `?variant=ember-paper`…).

## When you add a theme

Add `Theme/Themes/<id>.json` (every token; `kind` dark or light) and append the id to
`NotaThemes.BuiltInOrder`. Nothing else names a theme. Run the smoke test (`RunThemes`).
